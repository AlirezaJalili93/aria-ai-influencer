می تونی؟

بله، می‌توانم هم در تولید صفر تا صد محتوا و هم در ساخت و کدنویسی ایجنت خودکار برای مدیریت پیج همراهتان باشم. برای اینکه دقیقاً بدانید کدام بخش‌ها مستقیم در همین محیط انجام می‌شود و کدام بخش‌ها نیاز به اتصال به API اینستاگرام دارد:

سناریونویسی و کپشن‌نویسی: طراحی تقویم محتوایی، سناریوی ریلز و استوری، کپشن‌های تعاملی و پاسخ‌های آماده با لحن اختصاصی «اولین پیج هوش مصنوعی ایران» را مستقیم انجام می‌دهم.

تولید تصویر و ایده‌پردازی ویدیو/موشن: تصاویر پست و استوری را مستقیم برایتان می‌سازم و برای ویدیو یا موشن، هم می‌توانم اسکریپت‌های کدنویسی‌شده (مثل انیمیشن‌های تحت وب/پایتون) بسازم و هم پرامپت‌های دقیق صحنه به صحنه برای ابزارهای ویدیوساز هوش مصنوعی (مثل Runway یا Kling) آماده کنم.

زمان‌بندی استوری و مدیریت دایرکت و کامنت: از آنجایی که انتشار مستقیم روی پیج و پاسخ‌گویی ۲۴ ساعته به دایرکت و کامنت نیازمند اتصال به Instagram Graph API است، می‌توانم سورس‌کد کامل این ایجنت (با پایتون) یا ساختار اتوماسیون آن (مثل n8n) را برایتان بنویسم تا به اکانت بیزینسی خود وصل کنید؛ همچنین می‌توانم همین‌جا یک برنامه زمان‌بندی‌شده تنظیم کنم تا هر روز محتوای آماده استوری و پست را برایتان تولید کند.

برای اینکه کار را دقیق شروع کنیم، لطفاً این ۳ مورد را مشخص کنید:

مدل پیاده‌سازی: می‌خواهید کد کامل یک ایجنت نرم‌افزاری مستقل (با پایتون و اتصال به API اینستاگرام) برایتان بنویسم تا روی سرور اجرا کنید، یا می‌خواهید همین‌جا سیستم تولید محتوا، تصویر و سناریوی روزانه را برایتان راه‌اندازی کنم (یا ترکیبی از هر دو)؟

هویت و زاویه دید پیج: شعار «من اولین پیج هوش مصنوعی ایرانم» به این معنی است که پیج از زبان یک کاراکتر/اینفلوئنسر مجازی هوش مصنوعی صحبت می‌کند که خودش پیج را می‌گرداند، یا منظور یک رسانه آموزشی و خبری هوش مصنوعی است؟

لحن و سبک تعامل: ترجیح می‌دهید لحن پیج در کپشن‌ها و پاسخ به دایرکت‌ها چطور باشد (صمیمی و شوخ‌طبع، رازآلود و آینده‌نگرانه، یا کاملاً تخصصی و جدی)؟

سیستم ترکیبی مدیریت پیج «اولین اینفلوئنسر مجازی هوش مصنوعی ایران (آریا)» را در هر دو بخش (تولید محتوای خودکار در همین محیط + سورس‌کد ایجنت پایتون متصل به API اینستاگرام) برایتان راه‌اندازی و آماده کردم:

سورس‌کد کامل ایجنت خودکار اینستاگرام (instagram_ai_agent.py): اسکریپت پایتون آماده اجرا که به هوش مصنوعی جمینای و Instagram Graph API متصل می‌شود تا سناریو و کپشن بنویسد، ویدیوی موشن استوری (9:16 MP4) رندر بگیرد، استوری‌ها و ریلزهای زمان‌بندی‌شده را در ساعت مشخص منتشر کند و به دایرکت‌ها و کامنت‌ها با لحن صمیمی، شوخ‌طبع و آینده‌نگرانه پاسخ دهد.

دفترچه استراتژی، سناریوها و راهنمای راه‌اندازی (ai_influencer_playbook.md): شامل شناسنامه کاراکتر، گزینه‌های بیو، پرامپت ثابت حفظ چهره (Seed Prompt)، سناریوهای کامل و کپشن‌های آماده کپی هفته اول، برنامه ۳ استوری زمان‌بندی‌شده روزانه و پرامپت‌های متحرک‌سازی ویدیو در Kling و HeyGen.

زمان‌بندی خودکار روزانه در همین محیط: یک برنامه روزانه برای حدود ساعت ۹:۰۰ صبح تنظیم کردم تا هر روز به صورت خودکار سناریوی ریلز، کپشن، سناریوی ۳ استوری زنجیره‌ای و تصویر استوری همان روز را برایتان آماده کند.

فرمول ۳ استوری زمان‌بندی‌شده روزانه: استوری صبح (ساعت ۱۰:۰۰ - انرژی روزانه و نظرسنجی شوخ با زندگی انسانی)، استوری عصر (ساعت ۱۶:۰۰ - معرفی ترفند یا خبر آینده‌نگرانه با فراخوان ریپلای دایرکت) و استوری شب (ساعت ۲۱:۰۰ - باکس سوال و گپ شبانه با هوش مصنوعی).

سقف بودجه توکن روزانه (daily_token_limit): برای هر کلید API می‌توانید یک سقف مصرف روزانه (مثلاً ۵۰۰,۰۰۰ توکن در روز) تعیین کنید. به محض پر شدن سقف یک کلید در روز، ایجنت به صورت خودکار سراغ کلید بعدی می‌رود.

تفکیک هوشمند مدل بر اساس نوع تسک: ایجنت برای نوشتن سناریو و پکیج روزانه (SCENARIO_PACK) از مدل‌های قدرتمند (scenario_model) و برای پاسخ‌گویی ۲۴ ساعته به کامنت‌ها و دایرکت‌ها (DM_REPLY / COMMENT_REPLY) از مدل‌های سریع و اقتصادی (fast_model) استفاده می‌کند تا مصرف توکن بهینه بماند.

سوییچ خودکار در صورت خطا (Auto-Failover): در حالت --provider auto، اگر یک سرویس ارور محدودیت سرعت (429 Rate Limit) یا قطعی بدهد، ایجنت بدون توقف پیج، درخواست را با کلید پشتیبان بعدی انجام می‌دهد.

گزارش لحظه‌ای مصرف توکن (--token-report): تمام توکن‌های ورودی (prompt_tokens)، خروجی (completion_tokens) و کل (total_tokens) به تفکیک هر کلید و هر تسک در دیتابیس SQLite ثبت می‌شود.

persian-rtl-vazirmatn

Enforce Persian (Farsi) RTL text direction, UTF-8 encoding, Vazirmatn font selection, and anti-tofu (no square boxes) rendering across all generated files, scripts, images, videos, charts, web apps, and documents. Use whenever generating or editing Persian content, code that renders Persian text (Pillow, OpenCV, Matplotlib, Chromium), HTML/CSS, PDF, Word, PowerPoint, or Excel files.

Instructions
Persian RTL Vazirmatn

Ensure all Persian (Farsi) text across every output format is encoded in UTF-8, aligned Right-to-Left (RTL), styled with the Vazirmatn (وزیرمتن) typeface wherever selectable, and rendered with proper cursive shaping and glyph coverage so characters never appear as square boxes (□□□) or disconnected LTR letters.

When to Use
Generating or editing any file, document, web app, image, video, chart, or script containing Persian (Farsi) text
Writing Python scripts that draw text on images or videos using Pillow (PIL), OpenCV (cv2), or Matplotlib
Creating HTML/CSS web apps, PDFs, Word (.docx), PowerPoint (.pptx), Excel (.xlsx), or CSV files with Persian text
Steps
1. Enforce UTF-8 Encoding Everywhere
Add # -*- coding: utf-8 -*- at the top of Python scripts and always pass encoding="utf-8" when reading or writing files (encoding="utf-8-sig" for CSV files opened in Excel).
Add <meta charset="UTF-8"> as the first tag inside <head> in all HTML templates.
Pass ensure_ascii=False to JSON serialization calls so Persian strings remain readable UTF-8 rather than escaped Unicode sequences.
2. Apply Right-to-Left (RTL) Direction and Vazirmatn Typeface by Format

HTML / CSS / Chromium PDF / Web Apps:

Set <html lang="fa" dir="rtl">.

Apply global RTL rules with Vazirmatn as the primary typeface while isolating inline code blocks:

html, body {
  direction: rtl;
  text-align: right;
  font-family: 'Vazirmatn', 'Noto Sans Arabic', 'Tahoma', sans-serif;
}
pre, code, .ltr {
  direction: ltr;
  text-align: left;
  unicode-bidi: isolate;
}


Word (.docx), PowerPoint (.pptx), and Excel (.xlsx):

Set the primary typeface to "Vazirmatn", enable right-to-left paragraph/sheet direction (<w:bidi/> in Word, rtl="1" in PowerPoint, rightToLeft = True in Excel), and align text to the right.
3. Eliminate Square Boxes (□□□) in Pillow & OpenCV Image/Video Rendering

Never use cv2.putText() for Persian text because OpenCV built-in fonts only support ASCII and render question marks or boxes. Always render via Pillow (PIL.ImageDraw) with the Raqm layout engine (ImageFont.Layout.RAQM) and a font file that covers both Persian (آ-ی, گ چ پ ژ ک ی, ۰-۹) and Latin/ASCII (A-Z, 0-9, (, ), /, -):

Prioritize Vazirmatn: Check for local Vazirmatn-Bold.ttf and Vazirmatn-Regular.ttf first.
Build a Unified Fallback Font Offline: In offline Linux containers where Vazirmatn is not pre-installed, NotoSansArabic-Bold.ttf has Persian glyphs but lacks ASCII/Latin glyphs (A-Z, (, ), /), causing square boxes (□□□) on mixed Persian/English strings. Merge NotoSansArabic-Bold.ttf with NotoSans-Bold.ttf using fontTools.merge.Merger before loading with ImageFont.Layout.RAQM.
Draw with RTL Direction and Auto-Fit Right Anchor: Always pass direction="rtl", language="fa", and anchor="ra" positioned at x = canvas_width - right_margin, scaling down the font size if textbbox width exceeds canvas_width - 2 * margin.
Gotchas
Mixed Persian + English Strings: Passing English words (AI, Node 01) or ASCII punctuation ((, ), /) to a pure Arabic/Persian font like NotoSansArabic-Bold.ttf produces square boxes (□□□). Always use Vazirmatn or the merged NotoSansArabic + NotoSans font.
Left-Edge Clipping on RTL Text: When using anchor="ra" at right_x, long strings extend leftward (right_x - text_width). Always verify text_width <= max_width before drawing.

۲. امکانات مدیریت توکن و چرخش خودکار کلیدها (StateDatabase + MultiAIRouter)

گاوصندوق کلیدها با سقف بودجه روزانه (api_keys_vault): می‌توانید بی‌نهایت کلید API از شرکت‌های مختلف ثبت کنید و برای هر کدام یک سقف مصرف روزانه (--daily-limit مثلاً ۵۰۰,۰۰۰ توکن) و اولویت (--priority) تعیین کنید.

تفکیک هوشمند مدل برای کاهش مصرف توکن: ایجنت به صورت خودکار برای نوشتن سناریوی ریلز و پکیج محتوایی روزانه (SCENARIO_PACK) از مدل‌های سنگین و خلاق (scenario_model) و برای پاسخ به کامنت‌ها و دایرکت‌ها (DM_REPLY / COMMENT_REPLY) از مدل‌های سبک و کم‌مصرف (fast_model) استفاده می‌کند.

چرخش و جایگزینی خودکار (Auto-Failover): وقتی ایجنت روی حالت --provider auto باشد، به محض اینکه سقف توکن روزانه یک کلید پر شود یا ارور محدودیت سرعت (429 Rate Limit) بدهد، بدون توقف پیج به سراغ کلید بعدی در لیست اولویت می‌رود.

گزارش لحظه‌ای مصرف توکن (--token-report): تمام توکن‌های ورودی (prompt_tokens)، خروجی (completion_tokens) و درصد مصرف روزانه هر کلید در جدول token_usage_logs ذخیره شده و با یک دستور قابل مشاهده است.

اضافه کردن کلیدهای مختلف (بین‌المللی یا درگاه ایرانی) با سقف توکن روزانه:

قابلیت‌های مدیریت توکن و چرخش خودکار کلیدها (Token & Failover Management)

سقف بودجه توکن روزانه (daily_token_limit): برای هر کلید API می‌توانید یک سقف مصرف روزانه (مثلاً ۵۰۰,۰۰۰ توکن در روز) تعیین کنید. به محض پر شدن سقف یک کلید در روز، ایجنت به صورت خودکار سراغ کلید بعدی می‌رود.

تفکیک هوشمند مدل بر اساس نوع تسک: ایجنت برای نوشتن سناریو و پکیج روزانه (SCENARIO_PACK) از مدل‌های قدرتمند (scenario_model) و برای پاسخ‌گویی ۲۴ ساعته به کامنت‌ها و دایرکت‌ها (DM_REPLY / COMMENT_REPLY) از مدل‌های سریع و اقتصادی (fast_model) استفاده می‌کند تا مصرف توکن بهینه بماند.

سوییچ خودکار در صورت خطا (Auto-Failover): در حالت --provider auto، اگر یک سرویس ارور محدودیت سرعت (429 Rate Limit) یا قطعی بدهد، ایجنت بدون توقف پیج، درخواست را با کلید پشتیبان بعدی انجام می‌دهد.

گزارش لحظه‌ای مصرف توکن (--token-report): تمام توکن‌های ورودی (prompt_tokens)، خروجی (completion_tokens) و کل (total_tokens) به تفکیک هر کلید و هر تسک در دیتابیس SQLite ثبت می‌شود.
