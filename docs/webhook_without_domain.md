# وب‌هوک آزمایشی روی VPS بدون خرید دامنه

این راهنما با UTF-8 نوشته شده است؛ داشبورد همچنان از راست‌به‌چپ و فونت محلی وزیرمتن استفاده می‌کند.

این روش برای تست اتصال متا است. Cloudflare Quick Tunnel یک آدرس عمومی HTTPS موقت می‌دهد؛ خرید دامنه یا حساب Cloudflare لازم نیست. این سرویس تضمین پایداری ندارد و نام میزبان با شروع مجدد تونل عوض می‌شود. برای استفادهٔ دائمی باید آدرس ثابت تنظیم شود. ثبت آدرس و دسترسی‌های حساب در Meta همچنان لازم است.

## ساختار

تونل به `127.0.0.1:8081` وصل می‌شود. درگاه کوچک وب‌هوک فقط GET و POST روی مسیر دقیق `/webhook` را به سرویس محلی آریا می‌فرستد. داشبورد، فایل‌ها و API مدیریت از این مسیر عمومی پاسخ 404 می‌گیرند؛ حتی اگر درخواست هدر Host محلی داشته باشد. امضای `X-Hub-Signature-256` و بایت‌های بدنه بدون تغییر به آریا منتقل می‌شوند. بررسی Verify Token و App Secret در همان برنامهٔ اصلی انجام می‌شود.

پورت 8080 عمومی نمی‌شود. فایل `.env`، داده‌ها، کلیدها، فایروال و سرویس‌های دیگر تغییر نمی‌کنند. دو سرویس مستقل با کاربر پویا و بدون دسترسی به تنظیمات خصوصی آریا ایجاد می‌شوند:

- `aria-webhook-relay.service`: درگاه محدود به وب‌هوک روی loopback.
- `aria-webhook-tunnel.service`: اتصال خروجی Cloudflare با HTTP/2 و شروع خودکار پس از بوت.

## نصب روی AlmaLinux/RHEL

پس از به‌روزرسانی امن مخزن به نسخهٔ شامل این راهنما، با root اجرا کنید:

```bash
cd /opt/aria-ai-influencer
bash scripts/setup_webhook_tunnel.sh
```

نصب‌کننده وضعیت سرویس آریا و خالی بودن پورت 8081 را بررسی می‌کند. در صورت نبودن cloudflared، آن را از مخزن رسمی دارای امضای بسته نصب می‌کند؛ سرویس cloudflared دیگری را متوقف نمی‌کند. قبل از جایگزینی فایل‌های خودش، در `/root/aria-webhook-backup-*` نسخهٔ پشتیبان می‌سازد. سپس درگاه محلی و آدرس عمومی را واقعاً با HTTP آزمایش می‌کند. ثبت Callback URL فقط پس از عبور از این بررسی‌ها انجام می‌شود. اجرای مجدد، تونل فعال و آدرس فعلی آن را حفظ می‌کند.

نمونهٔ خروجی:

```text
Callback URL: https://RANDOM.trycloudflare.com/webhook
Public checks passed: dashboard/API blocked; webhook awaits Meta verification.
```

این خروجی نشان‌دهندهٔ آماده بودن مسیر شبکه است؛ اتصال حساب اینستاگرام یا اعتبار توکن‌های متا را اثبات نمی‌کند. GET بدون Verify Token معتبر باید 403 باشد. POST بدون App Secret تنظیم‌شده در آریا 503 می‌گیرد و امضای نامعتبر 403 می‌گیرد. سقف بدنهٔ ورودی در درگاه یک مگابایت است؛ درخواست با Transfer-Encoding یا Content-Length تکراری رد می‌شود.

## بعد از نصب

1. Callback URL را در بخش وب‌هوک محصول اینستاگرام اپ متا وارد کنید.
2. Verify Token همان `IG_WEBHOOK_VERIFY_TOKEN` تنظیم‌شده در آریا است؛ در داشبورد محلی نمایش داده می‌شود. آن را در چت عمومی نفرستید.
3. App Secret اپ متا باید در `META_APP_SECRET` فایل `.env` روی سرور ذخیره شود؛ سپس `systemctl restart aria-instagram-agent` اجرا شود. این راهنما هیچ مقدار فرضی برای App Secret نمی‌سازد و هیچ راز واقعی را در گیت ذخیره نمی‌کند.
4. اشتراک رویدادهای پیام و دسترسی‌های لازم باید در Meta فعال شود؛ حساب حرفه‌ای و اتصال Facebook Page مطابق مسیر Facebook Login فعلی پروژه لازم است. اتصال حساب از تب چهارم داشبورد انجام می‌شود.
5. دریافت و پاسخ یک دایرکت واقعی فقط بعد از تکمیل این مراحل قابل تأیید است.

برای بررسی آدرس فعلی و سلامت عمومی:

```bash
bash scripts/setup_webhook_tunnel.sh --status
```

این فرمان فقط گزارش اجرای فعلی تونل را می‌خواند تا آدرس قدیمی را گزارش نکند. بعد از ری‌استارت تونل یا VPS، آدرس را دوباره بررسی و در Meta اصلاح کنید. در صورت شکست بررسی عمومی، نصب‌کننده صریحاً خطا می‌دهد؛ نصب سرویس به‌تنهایی موفقیت شبکه محسوب نمی‌شود.

برای مشاهدهٔ خطای اتصال:

```bash
journalctl -u aria-webhook-tunnel -n 40 --no-pager
journalctl -u aria-webhook-relay -n 40 --no-pager
```

برای قطع انتشار وب‌هوک بدون توقف آریا و داشبورد:

```bash
bash scripts/setup_webhook_tunnel.sh --stop
```

دسترسی خصوصی داشبورد از PowerShell ویندوز:

```powershell
ssh -N -L 18080:127.0.0.1:8080 root@195.248.241.48
```

سپس در مرورگر `http://127.0.0.1:18080/dashboard` را باز کنید.

## منابع رسمی

- [مخزن رسمی بسته‌های cloudflared برای RHEL](https://pkg.cloudflare.com/)

آزمایش‌های محلی، چالش متا، بدنهٔ فارسی با امضای درست، امضای غلط، مسدود بودن مسیرهای مدیریت با Host جعلی محلی، محدودیت اندازه/متد/فریم‌بندی و قطع بودن سرویس بالادستی را بررسی می‌کنند. هیچ پیام واقعی، درخواست پولی هوش مصنوعی یا انتشار اینستاگرام در تست‌ها انجام نمی‌شود. نصب واقعی روی VPS و دسترسی Cloudflare از آن، تنها پس از اجرای دستور روی همان سرور قابل تأیید است.
