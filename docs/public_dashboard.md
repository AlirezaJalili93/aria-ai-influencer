# داشبورد اینترنتی با آدرس ثابت و ورود رمزدار

دسترسی قبلی داشبورد به تونل SSH وابسته بود. برای دسترسی از مرورگر موبایل یا رایانه، بدون باز نگه‌داشتن PowerShell، یک سرویس HTTPS مستقل روی IP ثابت VPS قرار می‌گیرد:

`https://195.248.241.48/dashboard`

این روش به خرید دامنه یا آدرس موقت Cloudflare نیاز ندارد. Let’s Encrypt صدور گواهی IP را با پروفایل `shortlived` پشتیبانی می‌کند. Caddy گواهی را دریافت و خودکار تمدید می‌کند. معتبر بودن HTTPS و باز بودن راه اتصال باید روی VPS واقعی بررسی شود؛ اجرای موفق تست محلی به معنی صادر شدن گواهی عمومی نیست.

## نصب

بعد از به‌روزرسانی امن مخزن با `scripts/update_from_git.sh`، به عنوان root اجرا کنید:

```bash
cd /opt/aria-ai-influencer
bash scripts/setup_public_dashboard.sh 195.248.241.48
```

در اولین اجرا، رمز ورود داشبورد دو بار در ترمینال درخواست می‌شود؛ هنگام تایپ نمایش داده نمی‌شود. رمز باید ۱۶ تا ۷۲ بایت UTF-8 باشد. رمز را فقط در همان ترمینال و صفحهٔ ورود HTTPS وارد کنید؛ برای کسی نفرستید. نام کاربری اولیه `aria` است. رمز خام در تنظیمات یا گیت ذخیره نمی‌شود؛ Caddy هش bcrypt آن را می‌خواند. اجرای دوباره، رمز قبلی را حفظ می‌کند.

نصب‌کننده ابتدا فعال بودن آریا و درگاه وب‌هوک را بررسی می‌کند. اگر پورت ۸۰ یا ۴۴۳ در اختیار سرویس دیگری باشد، متوقف می‌شود و تنظیمات وب‌سرور موجود را جایگزین نمی‌کند. باینری مستقل Caddy نسخهٔ 2.11.7 از انتشار رسمی با بررسی SHA-256 نصب می‌شود؛ سرویس‌ها یا باینری‌های Caddy دیگر دست‌کاری نمی‌شوند.

فایل‌های این سرویس:

- `/usr/local/bin/aria-dashboard-caddy`: باینری مستقل Caddy.
- `/etc/aria-dashboard/Caddyfile`: مسیرها، ورود رمزدار و تنظیم گواهی.
- `/etc/aria-dashboard/settings.json`: IP، نام کاربری و هش رمز.
- `/var/lib/aria-dashboard/`: گواهی‌ها و وضعیت پایدار Caddy، با دسترسی حساب اختصاصی.
- `aria-dashboard.service`: شروع خودکار پس از بوت و تلاش مجدد پس از خروج فرایند.

قبل از جایگزینی فایل‌های خودش، نصب‌کننده در `/root/aria-dashboard-backup-*` پشتیبان می‌گیرد. فایل `.env`، پایگاه داده، خروجی رسانه و کلیدهای API آریا تغییر نمی‌کنند. نصب این بخش، آریا یا تونل وب‌هوک موجود را ری‌استارت نمی‌کند.

## دسترسی شبکه

پورت‌های عمومی TCP 80 و 443 باید قابل دسترسی باشند. پورت 80 برای اعتبارسنجی گواهی و انتقال به HTTPS استفاده می‌شود؛ صفحهٔ ورود و داده‌های داشبورد از HTTPS عبور می‌کنند. اگر firewalld فعال باشد، نصب‌کننده فقط سرویس‌های `http` و `https` را در zone رابط پیش‌فرض شبکه، در وضعیت جاری و دائمی اضافه می‌کند؛ فایروال را reload یا پاک نمی‌کند. تغییرات اضافه‌شده در پوشهٔ پشتیبان ثبت می‌شوند. قوانین SSH و سایر سرویس‌ها تغییری نمی‌کنند.

اگر ارائه‌دهندهٔ VPS فایروال جداگانه دارد، پورت‌های 80 و 443 در پنل ارائه‌دهنده نیز باید باز باشند. نصب‌کننده به پنل آن دسترسی ندارد. نبود دسترسی خارجی یا مشکل صدور گواهی با خطا گزارش می‌شود؛ برای عبور از خطا، گواهی نامعتبر یا خودامضا جایگزین نمی‌شود.

## ورود و بررسی

پس از موفقیت نصب، در مرورگر هر دستگاه متصل به اینترنت، آدرس HTTPS را باز کنید. پنجرهٔ ورود مرورگر نام کاربری و رمز می‌خواهد. برای باز کردن داشبورد نیازی به نشست SSH نیست.

```bash
bash scripts/setup_public_dashboard.sh --status
```

این دستور زنجیره و نام گواهی HTTPS و نیاز به رمز در صفحه، API و فایل JavaScript را بررسی می‌کند. مسیر بدون توکن وب‌هوک باید 403 بگیرد. بررسی از خود سرور به‌تنهایی جای آزمایش ورود از اینترنت بیرون VPS را نمی‌گیرد.

برای خطاهای گواهی یا اتصال:

```bash
journalctl -u aria-dashboard -n 60 --no-pager
ss -ltnp '( sport = :80 or sport = :443 )'
```

برای تغییر رمز:

```bash
bash scripts/setup_public_dashboard.sh 195.248.241.48 --reset-password
```

برای توقف دسترسی عمومی، بدون توقف برنامهٔ آریا یا تونل قبلی:

```bash
bash scripts/setup_public_dashboard.sh --stop
```

## جداسازی مسیرها

تمام مسیرهای داشبورد، API مدیریت، تصویر، فونت و رسانه به نام کاربری و رمز نیاز دارند. Origin مرورگر و درخواست‌های cross-site قبل از تغییر هدرهای درخواست بالادستی بررسی می‌شوند. پس از احراز هویت، Host به نشانی محلی آریا تبدیل و اطلاعات ورود از درخواست بالادستی حذف می‌شود. برنامهٔ اصلی همچنان روی `127.0.0.1:8080` است و عمومی نمی‌شود.

ورود با کلیک روی لینک در یک سایت دیگر، مانند چت، باید به صفحهٔ ورود برسد. برای این حالت فقط درخواست GET با `Sec-Fetch-Mode: navigate` و `Sec-Fetch-Dest: document` اجازهٔ عبور از قاعدهٔ cross-site را دارد؛ رمز همچنان اجباری است. iframe، درخواست fetch/CORS و تغییرات POST از سایت دیگر مسدود می‌مانند. دستور `--status` این تفاوت را نیز آزمایش می‌کند. در صورت نمایش Access denied، ورود مستقیم با تایپ آدرس و ورود از لینک بیرونی را جداگانه بررسی کنید؛ نوع خطای 401 یا 403 و این‌که پنجرهٔ رمز ظاهر شده است، برای تشخیص کاربرد دارد.

فقط مسیر دقیق `/webhook` به درگاه محدود قبلی روی `127.0.0.1:8081` می‌رود؛ این مسیر ورود داشبورد نمی‌خواهد و همچنان Verify Token و امضای Meta را بررسی می‌کند. تونل موقت Cloudflare قبلی پابرجا می‌ماند؛ برای کارکرد داشبورد، تغییر Callback متا لازم نیست.

سرویس مستقل وب برای کار مداوم و تمدید خودکار گواهی تنظیم شده است؛ دسترسی به روشن بودن VPS، شبکه و باز ماندن پورت‌های اعتبارسنجی وابسته است.

تست‌های محلی از Caddy واقعی و CA داخلی مختص آزمایش استفاده می‌کنند؛ این حالت در نصب‌کنندهٔ سرور وجود ندارد. در محیط آزمایش، مسیرهای بدون رمز، ورود درست و غلط، رد Origin خارجی، تغییر تنظیمات در بک‌اند و امضای وب‌هوک بررسی می‌شوند. برای اجرای این تست‌ها مسیر یک باینری تأییدشدهٔ Caddy را تعیین کنید:

```bash
ARIA_TEST_CADDY=/path/to/caddy python -m unittest discover -s tests -v
```
