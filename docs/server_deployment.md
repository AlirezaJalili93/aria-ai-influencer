# راهنمای استقرار بررسی‌شدهٔ آریا

## وضعیت واقعی پروژه

هسته، یک برنامهٔ Python با SQLite و HTTP داخلی است. Router درخواست‌های متن را میان سرویس‌های AI جابه‌جا می‌کند و مصرف توکن را ثبت می‌کند. Daemon صف انتشار را پردازش و کامنت‌های اخیر را بررسی می‌کند. پیام‌های دایرکت از وب‌هوک دریافت می‌شوند.

- اجرای `--run-daemon`، HTTP و حلقهٔ زمان‌بندی را با هم فعال می‌کند؛ `--run-server` فقط HTTP را اجرا می‌کند.
- تولید پکیج روزانه یک فرمان/API است؛ اجرای Daemon به‌تنهایی هر روز محتوای جدید تولید نمی‌کند.
- فایل‌های `web/index.html` و `aria_ai_influencer_live.html` یک پنل نمایشی با برخی درخواست‌های مستقیم Meta هستند. دکمه‌های تست کلید، صف انتشار و پاسخ‌های نمونه، اثبات عملیات واقعی بک‌اند نیستند. انتشار مستقیم پنل فقط کانتینر مدیا می‌سازد و مرحلهٔ `media_publish` را کامل نمی‌کند.
- داشبورد عملیاتی جدید در `/` و `/dashboard` ارائه می‌شود (`web/dashboard.html`). ثبت کلید، اتصال پیج، تولید پاسخ و محتوا، ثبت/لغو زمان‌بندی و نمایش وضعیت به API واقعی Python متصل‌اند. فایل‌های HTML قدیمی همچنان نمونهٔ نمایشی هستند و مسیر داشبورد جدید آن‌ها را بارگذاری نمی‌کند.
- API مدیریت فعلی ورود کاربر ندارد. آن را روی اینترنت منتشر نکنید. تنظیم پیش‌فرض این نسخه اتصال محلی است؛ فقط `/webhook` باید با HTTPS عمومی شود.
- کلیدهای ذخیره‌شده در SQLite رمزگذاری نمی‌شوند. دسترسی فایل تنظیمات و پوشهٔ داده در نصب systemd محدود می‌شود.
- سبز بودن `/health` فقط به معنای پاسخ‌دهی HTTP است؛ اعتبار توکن متا، مجوزهای پیج، دریافت واقعی وب‌هوک، پاسخ AI یا انتشار واقعی را تضمین نمی‌کند.

## تغییرات مسیر اجرا

گزینهٔ نامعتبر `--serve-webhook` با `--run-daemon` جایگزین شده است. NumPy، Pillow و OpenCV headless به وابستگی‌ها اضافه شده‌اند. پایگاه داده در `data/` باقی می‌ماند و شکست نوشتن دیگر به تغییر مخفی مسیر به `/tmp` منجر نمی‌شود. درخواست POST وب‌هوک با `META_APP_SECRET` امضاسنجی می‌شود؛ بدون آن، دریافت رویداد خطای 503 می‌دهد. نصب، فایروال را تغییر نمی‌دهد و مخزن را reset نمی‌کند.

## ۲. دریافت نسخه و نصب

در نصب اول، شاخهٔ اصلاحات را جداگانه دریافت کنید:

```bash
git clone --branch codex/prepare-server-deployment --single-branch https://github.com/AlirezaJalili93/aria-ai-influencer.git /opt/aria-ai-influencer
cd /opt/aria-ai-influencer
bash scripts/server_git_deploy.sh --check
bash scripts/server_git_deploy.sh
```

اگر مسیر `/opt/aria-ai-influencer` از قبل وجود دارد، دستور clone را اجرا نکنید؛ ابتدا وضعیت فایل‌ها، شاخه، سرویس و دیتابیس موجود بررسی شود.

نصب، محیط مجزای Python، کاربر `aria-agent` و فایل تنظیمات را ایجاد می‌کند. تنظیمات موجود و فایل سرویس قبل از تغییر نسخهٔ پشتیبان می‌گیرند. اگر دیتابیس جدید وجود نداشته باشد و تنها یکی از دیتابیس‌های قدیمی `/tmp/instagram_agent_state.db` یا `/opt/aria_instagram_agent/data/instagram_agent_state.db` پیدا شود، با API پشتیبان SQLite به مسیر پایدار کپی می‌شود. با وجود چند دیتابیس قدیمی، انتخاب باید بعد از بررسی انجام شود و نصب متوقف می‌شود. فایل اصلی حذف نمی‌شود.

نصب اولیه با کلیدهای خالی فقط HTTP را بالا می‌آورد؛ اتصال به متا یا ارسال پاسخ انجام نمی‌شود. روی نصب موجود با کلیدهای واقعی، اجرای مجدد سرویس می‌تواند پردازش صف و پاسخ‌دهی را از سر بگیرد.

## ۳. تنظیم کلیدها روی خود سرور

```bash
sudoedit /opt/aria-ai-influencer/.env
```

مقادیر لازم:

| متغیر | کاربرد |
| --- | --- |
| `IG_ACCESS_TOKEN` | توکن معتبر متا با مجوزهای لازم پیج |
| `IG_USER_ID` | شناسهٔ Business/Creator پیج |
| `GEMINI_API_KEY` یا کلید یکی از Providerها | تولید متن و پاسخ |
| `IG_WEBHOOK_VERIFY_TOKEN` | رمز توافقی تأیید Callback؛ نصب اولیه مقدار تصادفی ایجاد می‌کند |
| `META_APP_SECRET` | App Secret اپ متا برای بررسی امضای رویدادهای ورودی |
| `IG_GRAPH_VERSION` | نسخهٔ Graph API مورد استفاده؛ پیش‌فرض فعلی پروژه `v21.0` است |
| `AGENT_DB_PATH` | مسیر دائمی دیتابیس؛ در نصب استاندارد زیر `data/` |
| `TZ` | منطقهٔ زمانی اجرای برنامه؛ `Asia/Tehran` |

کلیدها را در چت، مخزن، URL یا دستورهای قابل ثبت در history وارد نکنید. مدل و نسخهٔ API باید با حساب و سرویس فعال شما آزمایش شوند.

```bash
systemctl restart aria-instagram-agent
systemctl is-active aria-instagram-agent
curl --fail http://127.0.0.1:8080/health
journalctl -u aria-instagram-agent -n 50 --no-pager
```

`instagram_connected` در وضعیت فعلی صرفاً وجود اطلاعات پیکربندی را نشان می‌دهد؛ تست اعتبار متا نیست.

## ۴. HTTPS و وب‌هوک

برای متا، دامنهٔ واقعی با گواهی معتبر لازم است. پورت 8080 خصوصی باقی بماند. در Reverse Proxy فقط مسیر دقیق زیر به برنامه هدایت شود؛ `/api/` و `/` را عمومی نکنید:

```nginx
location = /webhook {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 1m;
}
```

این قطعه داخل پیکربندی HTTPS دامنه قرار می‌گیرد و به‌تنهایی گواهی یا DNS نمی‌سازد. Callback در متا `https://YOUR_DOMAIN/webhook` است. مقدار Verify Token همان فایل تنظیمات و App Secret همان اپ متاست. فعال‌بودن مجوزها و Subscription وب‌هوک باید در خود Meta تأیید شود.

برای دسترسی خصوصی به API از PowerShell تونل باز کنید:

```powershell
ssh -N -L 18080:127.0.0.1:8080 root@195.248.241.48
```

داشبورد در مرورگر ویندوز: `http://127.0.0.1:18080/dashboard`. پنجرهٔ PowerShell تونل را باز نگه دارید. وضعیت JSON همچنان در `http://127.0.0.1:18080/api/status` در دسترس است. داشبورد به میزبان محلی و Origin همان آدرس محدود است؛ آن را بدون احراز هویت عمومی نکنید.

## Docker

```bash
cp .env.example .env
# تنظیم مقادیر واقعی در فایل .env روی سرور
mkdir -p data
docker compose up -d --build
docker compose ps
docker compose logs --tail=50
```

پورت میزبان فقط روی loopback منتشر می‌شود و دیتابیس روی Volume داده باقی می‌ماند. systemd و Docker را هم‌زمان برای یک پیج/دیتابیس اجرا نکنید. راهنمای نصب systemd فایل Verify Token را مقداردهی می‌کند؛ در مسیر Docker باید خودتان مقدار تصادفی خصوصی را در `.env` ثبت کنید.

## اعتبارسنجی انجام‌شده و باقی‌مانده

تست آفلاین:

```bash
python -m unittest discover -s tests -v
```

تست‌های داشبورد با یک Provider ساختگی محلی، ثبت کلید، تولید پاسخ و محتوا، ثبت/لغو صف و ثبت مصرف را بدون تماس با API واقعی بررسی می‌کنند. زمان‌های ورودی داشبورد به وقت تهران تفسیر می‌شوند و لغو فقط پیش از شروع پردازش امکان‌پذیر است. مورد PROCESSING پس از توقف ناگهانی نیازمند بررسی است و خودکار دوباره منتشر نمی‌شود. تست‌ها شروع واقعی HTTP در حالت سرور و Daemon بدون کلید، تأیید Callback، رد امضای نادرست، پذیرش امضای درست با رویداد خالی، رد JSON نامعتبر و ماندگاری SQLite را بررسی می‌کنند. هیچ پیام، کامنت یا محتوایی در این آزمون‌ها ارسال نمی‌شود.

تست systemd، ساخت Docker، دسترسی HTTPS متا، اعتبار توکن‌ها و انتشار واقعی باید روی سرور مقصد و با حساب واقعی انجام شوند. تا تکمیل آن‌ها، راه‌اندازی عملیاتی تأییدشده نیست.

## انتقال کامل استودیو و شخصیت

فهرست جزءبه‌جزء در `docs/restoration_inventory.md` است. با نسخهٔ جدید، اسکیل، شخصیت، منابع مرجع و فونت‌ها نیز در checkout سرور قرار می‌گیرند؛ اسکیل پروژه در `.agents/skills/` است و نصب جهانی در محیط Gemini یا ChatGPT انجام نمی‌دهد.

برای به‌روزرسانی از یک نصب قبلی، `scripts/update_from_git.sh` نسخهٔ Git انتخاب‌شده را fetch می‌کند، تغییرات tracked محلی را بررسی می‌کند، سرویس را موقتاً متوقف می‌کند و از تمام فایل‌ها از جمله `.env`، دیتابیس و رسانه‌ها (به جز `.git` و `.venv`) آرشیو root-only می‌گیرد. سپس نسخه را نصب، سلامت را بررسی و فایل‌ها را با manifest تطبیق می‌دهد. خطا باعث برگشت کد، تنظیمات و واحد systemd به نسخهٔ قبلی می‌شود؛ رکوردهای جدید دیتابیس پاک نمی‌شوند. نام مسیر بک‌آپ چاپ می‌شود.

```bash
cd /opt/aria-ai-influencer
git fetch origin codex/prepare-server-deployment
git show FETCH_HEAD:scripts/update_from_git.sh > /root/aria-update.sh
bash /root/aria-update.sh codex/prepare-server-deployment
```

بعد از نصب، در یک PowerShell جدید روی کامپیوتر خودتان تونل را باز نگه دارید:

```powershell
ssh -N -L 18080:127.0.0.1:8080 root@195.248.241.48
```

داشبورد: http://127.0.0.1:18080/dashboard

فونت محلی وزیرمتن و Pillow دارای RAQM برای رندر فارسی استفاده می‌شوند. رندر MP4 محلی برای دانلود قابل استفاده است؛ برای سازگاری بیشتر پخش وب و متا، نصب ffmpeg دارای libx264 باعث تبدیل خودکار خروجی می‌شود. نشانی محلی فایل برای متا قابل دریافت نیست؛ پیش از افزودن به صف انتشار، رسانه را روی میزبان HTTPS عمومی قرار دهید.

کلید OpenAI یا درگاه‌های متنی از تب کلیدها ثبت می‌شود. صدا از `ELEVENLABS_API_KEY` و `ELEVENLABS_VOICE_ID` در `.env` استفاده می‌کند. مدل تصویر از `OPENAI_IMAGE_MODEL` (پیش‌فرض `gpt-image-1`) انتخاب می‌شود. هزینه و دسترسی مدل‌ها با ارائه‌دهنده است و اتصال پولی در آزمون محلی انجام نشده است.
