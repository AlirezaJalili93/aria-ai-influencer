# صدای فارسی کاراکتر آریا با OpenAI

داشبورد برای تولید صدای کاراکتر از OpenAI Speech استفاده می‌کند. کلید داخلی ChatGPT قابل دریافت یا انتقال به سرور نیست؛ یک کلید API متعلق به صاحب پروژه با دسترسی و اعتبار مالی لازم است. کلید در سرور نگهداری می‌شود و درخواست تولید صدا از مرورگر مستقیم به OpenAI نمی‌رود.

## استفاده از داشبورد

1. در تب مدیریت کلیدها، ارائه‌دهندهٔ `OpenAI` و کلید API خودتان را ثبت کنید. کلید فعال باید در صندوق کلید موجود باشد؛ وجود کلید ElevenLabs لازم نیست. متغیر `OPENAI_API_KEY` نیز هنگام شروع سرویس به همین صندوق منتقل می‌شود.
2. تب سوم را باز کنید. در بخش رسانه، متن فارسی، صدای کاراکتر، سرعت و راهنمای لحن را انتخاب کنید.
3. «تولید صدای آریا با OpenAI» را بزنید. در صورت موفقیت، پخش‌کننده و لینک دانلود MP3 نمایش داده می‌شوند. فایل و تاریخچه در `data/` باقی می‌مانند؛ تولید صدا باعث انتشار اینستاگرام نمی‌شود.
4. انتخاب صدا، سرعت و لحن پس از تولید موفق ذخیره می‌شوند و بعد از بازکردن دوبارهٔ داشبورد یا ری‌استارت برنامه نیز باقی می‌مانند. متن هر اجرا جداگانه وارد می‌شود.

مشخصات اولیهٔ صدا در `character/aria.json` تعریف شده‌اند: مدل `gpt-4o-mini-tts`، صدای `cedar` و سرعت `1.0`. راهنمای لحن، گفتار فارسی ایران با تلفظ طبیعی تهران و شخصیت صمیمی، شوخ و آینده‌نگر آریا را درخواست می‌کند. این دستور توصیف لحن است؛ کیفیت و تلفظ واقعی باید با گوش دادن به فایل ساخته‌شده بررسی شود. انتخاب یک صدای پایه و تنظیمات یکسان به یکدستی کمک می‌کند، اما تقلید یا شبیه‌سازی صدای یک انسان مشخص نیست.

## تنظیمات و درخواست واقعی

درخواست سرور به نشانی `/audio/speech` زیر Base URL همان کلید OpenAI ارسال می‌شود؛ برای سرویس اصلی، نشانی کامل `https://api.openai.com/v1/audio/speech` است. سرور، `model`، `voice`، متن `input`، راهنمای `instructions`، سرعت `speed` و `response_format=mp3` را می‌فرستد. کلیدهای سرویس‌های متنی دیگر به عنوان کلید OpenAI استفاده نمی‌شوند. درگاه سازگار فقط اگر با ارائه‌دهندهٔ OpenAI و Base URL درست ثبت شده و endpoint صدا را پشتیبانی کند قابل استفاده است.

متن باید ۱ تا ۴۰۹۶ نویسه، سرعت بین ۰٫۲۵ و ۴ و راهنمای لحن ۱ تا ۲۰۰۰ نویسه باشد. مدل با `OPENAI_TTS_MODEL` و صدای اولیه با `OPENAI_TTS_VOICE` قابل تنظیم است. گزینهٔ ذخیره‌شدهٔ کاربر بر صدای اولیه اولویت دارد. مدل‌های قدیمی `tts-1` و `tts-1-hd` راهنمای لحن را نمی‌پذیرند؛ در صورت انتخاب این مدل‌ها، این فیلد ارسال نمی‌شود و ممکن است همهٔ صداهای فهرست در آن مدل‌ها در دسترس نباشند.

خطای HTTP، پاسخ JSON به جای صدا، پاسخ خالی یا بزرگ‌تر از ۲۰ مگابایت به عنوان MP3 موفق ذخیره نمی‌شود. بررسی نوع محتوا و سرآیند MP3 انجام می‌شود؛ این بررسی، ارزیابی شنیداری کیفیت نیست. خطا در تاریخچه ثبت می‌شود و تکرار خودکار درخواست پولی انجام نمی‌شود. در هر فرایند آریا فقط یک تولید صدا هم‌زمان اجرا می‌شود.

کلیدهای متوقف یا دارای بودجهٔ متنی تمام‌شده انتخاب نمی‌شوند. پاسخ دودویی MP3 مصرف توکن را گزارش نمی‌کند؛ بنابراین برنامه عدد توکن یا هزینهٔ فرضی برای صدا در نمودار نمی‌سازد. هزینهٔ صدا جداگانه در حساب OpenAI محاسبه می‌شود؛ بودجهٔ توکنی داشبورد سقف هزینهٔ تولید صدا را تضمین نمی‌کند. برای سقف هزینه از تنظیمات بودجه و دسترسی پروژه در حساب API استفاده کنید.

کلید و متن پاسخ خطای ارائه‌دهنده در نتیجهٔ صدا یا تاریخچهٔ خطا بازتاب داده نمی‌شوند. کلید ElevenLabs موجود و تابع قدیمی حذف نشده‌اند تا سازگاری و داده‌ها حفظ شوند، ولی مسیر داشبورد فقط OpenAI را فراخوانی می‌کند.

## نصب و تست روی VPS

از `scripts/update_from_git.sh` برای به‌روزرسانی همراه با پشتیبان و حفظ داده‌ها استفاده کنید. تونل عمومی وب‌هوک را برای این تغییر ری‌استارت نکنید؛ تغییر صدای داشبورد نیازی به عوض شدن آدرس متا ندارد. پس از به‌روزرسانی، صفحهٔ داشبورد را تازه‌سازی و یک متن کوتاه تولید کنید. هیچ کلیدی را در چت یا گیت قرار ندهید.

### تشخیص خطای 429

داشتن کلید به تنهایی اعتبار مالی API را تأمین نمی‌کند. پرداخت و موجودی API از اشتراک ChatGPT جداست. در [حساب API](https://platform.openai.com/settings/organization/billing/overview)، سازمان و پروژهٔ مربوط به همان کلید را انتخاب کنید و Billing، Usage و Limits را ببینید.

| کد امن نمایش‌داده‌شده | معنی و اقدام |
| --- | --- |
| `credit_balance_exhausted` | موجودی پیش‌پرداخت تمام شده؛ Billing را بررسی کنید. |
| `insufficient_quota` | سهمیه یا اعتبار کافی نیست؛ Billing و Limits را بررسی کنید. این کد به تنهایی ثابت نمی‌کند دقیقاً کدام سقف رسیده است. |
| `organization_spend_limit_exceeded` / `project_spend_limit_exceeded` | سقف هزینهٔ سازمان یا پروژه رسیده است؛ تنظیمات همان سطح را بررسی کنید. |
| `organization_usage_limit_exceeded` | سقف مصرف اختصاص‌یافته از طرف OpenAI رسیده است؛ افزایش محدودیت یا پشتیبانی لازم است. |
| `rate_limit_exceeded` / `slow_down` / نوع `rate_limit_error` | محدودیت سرعت؛ بین درخواست‌ها فاصله بدهید و مصرف هم‌زمان همین سازمان/پروژه را بررسی کنید. |
| بدون کد شناخته‌شده | علت قطعی قابل تشخیص نیست؛ برنامه کمبود اعتبار را حدس قطعی نمی‌زند. |

برنامه فقط کدها و نوع‌های شناخته‌شده را از پاسخ خطای حداکثر ۶۴ کیلوبایتی می‌خواند؛ متن خام خطا، مقادیر ناشناخته و هدرهای ارائه‌دهنده در خروجی یا تاریخچه ذخیره نمی‌شوند. `provider_code` کد واقعیِ شناخته‌شده است؛ اگر فقط نوع خطا مشخص باشد، `provider_code` خالی و `provider_type` تنظیم می‌شود. کد مشخص بر نوع کلی اولویت دارد.

خطای ارائه‌دهندهٔ 429 اکنون از `/api/generate-voice` نیز با HTTP 429 و همین جزئیات امن برمی‌گردد؛ نسخهٔ قبلی همهٔ خطاهای این مسیر را به 400 تبدیل می‌کرد و جزئیات علت را حذف می‌کرد. خطاهای HTTP دیگرِ ارائه‌دهنده با 502 و `provider_status` اصلی گزارش می‌شوند؛ برای 401 احراز هویت و برای 403 دسترسی را بررسی کنید. پیام امن در تاریخچهٔ کار ناموفق نیز می‌ماند. درخواست پولی خودکار تکرار نمی‌شود. اصلاح پیام خطا، حساب فاقد اعتبار یا محدودیت‌دار را فعال نمی‌کند.

برای اشتراک‌گذاری خطا فقط JSON امن پاسخ را بفرستید؛ هدر `Authorization` مرورگر حاوی اطلاعات ورود داشبورد است. اگر آن را منتشر کرده‌اید، روی VPS دستور `bash scripts/setup_public_dashboard.sh 195.248.241.48 --reset-password` را از پوشهٔ پروژه اجرا کنید و رمز جدید را فقط در اعلان مخفی ترمینال وارد کنید.

آزمایش‌های خودکار از یک سرویس محلی آزمایشی استفاده می‌کنند و دسترسی حساب واقعی یا کیفیت تلفظ فارسی را تأیید نمی‌کنند.
